# 样本量变更记录

本文件用于记录每次样本量调整的时间、理由和当时已知的结果。
目的：文章中报告统计检验时，能如实披露样本量不是事后挑出来的。

## 变更 1 —— 2026-09-01

**调整前**：A22 / B16 / C22 / D16 / E12 / F12 / G12 / H16（每模型）

**当时已知的结果**：全部任务合并，-Fin 无答案 8/114（7.0%），基座 2/112（1.8%），
Fisher 双侧 p = 0.102，两组 95% 置信区间重叠。

**调整理由**：p 值不显著，样本量不足以支持"-Fin 静默失败更多"的断言。
按 RULES.md「结论不超过证据」，需要扩样才能决定这条能否写。
扩样集中在**已观察到失败的任务**（A、C、D、F），G/H 零失败不扩。

**调整后**：A42 / C42 / D30 / F24 / H24（每模型），B、E、G 不变。

## 变更 2 —— 2026-09-01（F 单项）

**当时已知的结果**：
- 任务 F 两臂各 24 轮：-Fin 5/24（20.8%），基座 0/24（0%），Fisher 双侧 **p = 0.0496**
- 全部任务：-Fin 10/144，基座 2/140，Fisher 双侧 p = 0.0349

**调整理由**：F 的 p = 0.0496 贴着 0.05 边界，稳健性不足——增减一轮即可能翻转结论。
F 是效应最集中的格子（长输出任务），值得给足样本量。
**本次扩样在看到扩样后数据之前决定，最终结果无论显著与否都如实报告。**

**调整后**：F 由每模型 24 轮提高至 **48 轮**。

**文章披露要求（强制）**：
> 任务 F 最初计划每臂 24 轮，得到 p=0.0496；因该值处于临界，
> 我们在获取新数据前声明将样本扩至每臂 48 轮，并报告最终结果。

不得只报告扩样后更有利的数字而隐去本次变更。


## 数据剔除 —— 2026-09-01（自查发现）

**问题**：`run_python` 工具早期存在路径拼接 bug（相对路径同时用作 cwd 与脚本路径，
导致子进程解析出双层目录）。修复于任务 B 期间，但**任务 A 与 E 的部分早期轮次在修复前已跑完**，
当时误判为「未使用 run_python，不受影响」。

**影响范围**：6 轮，全部在 -Fin 一侧（A r0/r2/r9/r13/r15、E r4），共 14 次工具调用作废。
偏差为单向：A 的 -Fin 最先执行，故污染只落在 -Fin。

**具体后果**：
- 任务 A 的 -Fin 均调用次数由 9.8 虚高（剔除后 8.5），此前多次对外表述的
  「-Fin 调用次数是基座 2.4 倍」被本次 bug 放大，实际约 1.7 倍。
- **A r15 被判定为「无答案 / 迭代耗尽」，实为模型反复重试失败的 run_python 所致，
  是记在模型头上的假失败**，直接污染核心指标。

**处理**：6 轮全部剔除，不补跑（-Fin 免费额度已于当日耗尽）。

**文章披露要求（强制）**：需说明测试工具本身出现过 bug、影响 6 轮、已剔除，
并说明剔除后 A 的调用次数差距由 2.4 倍修正为约 1.7 倍。
